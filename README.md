# Minideck

Небольшой самостоятельный аналог AnyDesk: удалённый рабочий стол на Python.
Один и тот же файл программы работает и как «хост» (компьютер, которым управляют),
и как «клиент» (компьютер, с которого управляют).

## Возможности

- Трансляция экрана 15, 30 или 45 кадров в секунду (выбор на панели окна просмотра); передаются только
  изменившиеся участки (JPEG-тайлы)
- Управление мышью и клавиатурой, горячие клавиши (Win, Alt+Tab, Ctrl+Shift+Esc …)
- Подключение по IP в локальной сети или по 9-значному ID через свой relay-сервер
- Сквозное шифрование (ChaCha20-Poly1305, ключ из пароля через scrypt) — relay видит только шифртекст
- Пароль доступа + запрос подтверждения на стороне хоста, блокировка после 5 неверных паролей в минуту
- Общий текстовый буфер обмена, отправка файлов на хост (в `Загрузки\Minideck`)
- Режим «только просмотр», выбор качества и масштаба, полноэкранный режим
- Сервер управления для организаций: учётные записи с ролями, список компьютеров, журнал действий

## Установка

Нужен Python 3.10+.

```bash
pip install -r requirements.txt
```

## Запуск

Окно программы — двойной щелчок по `Minideck.bat` или:

```bash
python -m minideck
```

Слева — данные **этого** компьютера (адрес, ID, пароль), справа — поле для подключения к **удалённому**.

### Готовый exe

`build.bat` собирает `dist\Minideck.exe` — один файл, Python на целевом компьютере не нужен, —
и установщик `dist\MinideckSetup.exe` (см. «Установка на клиентские ПК»).
Двойной щелчок открывает окно; те же команды работают из консоли:
`Minideck.exe host --password ...`, `Minideck.exe relay`.

### В локальной сети

1. На обоих компьютерах запустите Minideck.
2. На клиенте введите адрес хоста (например `192.168.1.20`) и пароль из его окна, нажмите «Подключиться».
3. На хосте подтвердите входящее подключение.

При первом запуске Windows спросит разрешение брандмауэра для Python — разрешите для частных сетей (порт 7070/TCP).

### Через интернет, по ID

Нужен компьютер с публичным адресом (VPS), на котором работает relay:

```bash
python -m minideck relay --port 7071
```

На обоих компьютерах впишите адрес relay в «Настройки → Relay-сервер» и нажмите «Применить».
Когда рядом с ID появится «в сети», к хосту можно подключаться по его ID из любой сети.
Relay только сводит два соединения и пересылает зашифрованные байты.

Без relay через интернет можно работать по IP, пробросив порт 7070 на роутере, или через VPN (Tailscale, WireGuard и т. п.).

## Сервер управления (для организаций)

Сервер хранит учётные записи с ролями и список компьютеров организации. Администратор входит на сервер
из окна Minideck, видит все компьютеры и подключается к ним без локального пароля.

### 1. Запустить сервер

Серверу нужна машина, доступная и администраторам, и клиентским ПК, с открытым портом **7072/TCP**.
`--public` — адрес, по которому клиентские ПК будут к нему обращаться (DNS-имя или IP); он попадает
в код регистрации.

При первом запуске сервер создаёт учётную запись `admin`, печатает её пароль и **записывает его в файл
`ADMIN-PASSWORD.txt` в папке данных** — так пароль не теряется, если сервер работает как служба или в
контейнере. Файл удаляется сам, как только пароль `admin` сменён в консоли. Забыли пароль — запустите
сервер с `--reset-admin`.

В папке данных лежат база (пользователи, компьютеры, журнал), сертификат и ключ TLS — делайте её
резервную копию. Сменился ключ — клиентским ПК придётся регистрироваться заново.

**Linux, Docker** (рекомендуется для VPS):

```bash
# в docker-compose.yml укажите MINIDECK_PUBLIC, затем:
docker compose up -d
docker compose logs          # пароль admin и код регистрации
```

Данные хранятся в томе `minideck-data`, контейнер работает не от root, перезапускается сам и корректно
останавливается по `docker stop`. Сброс пароля: `docker compose run --rm minideck-server --reset-admin`.

**Linux без Docker** — служба systemd: инструкция по установке в начале файла
`deploy/linux/minideck-server.service`. Пароль: `journalctl -u minideck-server`.

**Windows** — `MinideckServer.exe` (консольная программа, собирается `build.bat`):

```bash
MinideckServer.exe --public server.example.com
```

Чтобы сервер работал постоянно и запускался вместе с Windows, положите рядом с `MinideckServer.exe`
скрипты из `deploy\windows` и выполните в PowerShell, запущенном от имени администратора:

```bash
.\install-server.ps1 -Public server.example.com
```

Скрипт копирует сервер в `C:\Program Files\MinideckServer`, данные хранит в
`C:\ProgramData\MinideckServer` (доступ только у администраторов и SYSTEM), создаёт задачу планировщика
«Minideck Server» (запуск при загрузке от SYSTEM, перезапуск при сбое) и открывает порт в брандмауэре.
Удаление: `.\uninstall-server.ps1` (данные сохраняются; `-RemoveData` удалит и их).

**Из исходников**: `python -m minideck server --public server.example.com` (данные в `~/.minideck-server`
или в папке из переменной `MINIDECK_DATA`).

### 2. Войти администратором

В окне Minideck нажмите «Сервер управления», введите адрес сервера, логин и пароль. Откроется консоль:

| Вкладка | Что в ней |
|---|---|
| Компьютеры | список с поиском и статусом «в сети», кнопка «Подключиться», названия и группы |
| Пользователи | учётные записи, роли, доступ к группам |
| Журнал | все действия: входы, сеансы, файлы, буфер, изменения прав — виден всем ролям |
| Добавить компьютер | код регистрации для клиентских ПК |

### 3. Подключить клиентские ПК

Удобнее всего — установщиком (следующий раздел): он сразу подключит ПК к серверу. Вручную: на ПК
пользователя запустите Minideck, в строке «Сервер организации» нажмите «Подключить» и вставьте код
регистрации.

## Установка на клиентские ПК

`dist\MinideckSetup.exe` — мастер установки. Права администратора не нужны: программа ставится для
текущего пользователя Windows.

Что он делает (всё видно и удаляется):

- копирует программу в `%LOCALAPPDATA%\Programs\Minideck`;
- создаёт ярлык в меню «Пуск» и, по желанию, на рабочем столе;
- по желанию включает запуск при входе в Windows (окно открывается свёрнутым на панель задач);
- добавляет Minideck в «Параметры → Приложения», откуда его можно удалить;
- по желанию подключает компьютер к серверу организации.

**Код сервера заранее.** Положите рядом с `MinideckSetup.exe` файл `minideck-server.txt` с кодом
регистрации из консоли (вкладка «Добавить компьютер») — мастер подставит его сам. Можно и параметром:
`MinideckSetup.exe --code=minideck://...`. При первом запуске программа подключится к серверу, откроет
окно (даже при автозапуске) и покажет пользователю, что это значит: кто сможет подключаться, как
выглядят запрос и плашка, где журнал и как отключиться от сервера.

**Обновление.** Установленная программа сама проверяет новые версии (см. «Автообновление»). Вручную:
запустите новый `MinideckSetup.exe` поверх — он найдёт установленную версию, предложит закрыть запущенную
программу и заменит файлы; настройки, ID и журнал сохраняются.

### Автообновление

При запуске и затем раз в 6 часов программа смотрит последний релиз в
[GitHub Releases](https://github.com/F1sine/minideck/releases). Если вышла новая версия, в окне появляется
полоса «Доступна новая версия» с кнопками **Обновить**, **Что нового** и ✕. Без нажатия «Обновить»
ничего не устанавливается.

По нажатию «Обновить» программа скачивает `MinideckSetup.exe` из релиза и сверяет его SHA-256 с суммой,
которую публикует GitHub; если суммы нет или она не совпала, установка отменяется. Затем установщик
в режиме обновления дожидается закрытия программы, ставит новую версию в ту же папку с теми же ярлыками
и автозапуском и запускает её. В журнал компьютера пишутся «запущено обновление» и «программа обновлена».

- Пока к компьютеру кто-то подключён, обновление не запускается — чтобы не оборвать сеанс.
- Обновляется только копия, поставленная установщиком. Для `Minideck.exe` без установки и запуска из
  исходников кнопка называется «Скачать» и открывает страницу релиза.
- Черновики и пре-релизы не предлагаются.
- Отключить проверку: «Настройки → Обновления». Там же кнопка «Проверить сейчас».
- Свой источник обновлений (например, зеркало внутри организации): параметр `update_source` в
  `~/.minideck/config.json` — адрес в формате GitHub Releases API (`…/releases/latest`).

Автообновление появилось в версии 0.5.0: компьютеры на 0.4.0 и старше нужно один раз обновить вручную.
Безопасность обновлений держится на HTTPS и на защите аккаунта GitHub, с которого публикуются релизы:
включите на нём двухфакторную аутентификацию.

**Удаление.** «Параметры → Приложения → Minideck → Удалить» (или `Minideck.exe uninstall`). Можно
отметить «удалить настройки и журнал». На сервере компьютер останется как «не в сети» — удалите его
в консоли, если он больше не нужен.

Брандмауэр: для работы через сервер нужны только исходящие соединения, правила не требуются.
Входящий порт 7070 нужен лишь для прямых подключений по IP — Windows спросит разрешение при первом запуске.

### Роли

| Роль | Права |
|---|---|
| Администратор | всё: сеансы с управлением, пользователи, компьютеры, журнал, код регистрации |
| Оператор | просмотр и управление компьютерами своих групп |
| Наблюдатель | только просмотр компьютеров своих групп |

Группа назначается компьютеру в консоли; пользователю выдаётся список групп или `*` (все компьютеры).

### Что видит пользователь клиентского ПК

Программа на клиентском ПК работает открыто, это сделано намеренно:

- в окне видно, что компьютер подключён к серверу организации, и есть кнопка «Отключить»;
- при подключении показывается запрос с именем учётной записи (переключатель «Спрашивать перед
  подключением» есть только у пользователя — сервер не может его выключить);
- пока идёт сеанс, поверх экрана висит плашка «к этому компьютеру подключён …» с кнопкой «Отключить»;
- переключатель «Разрешить управление» на ПК сильнее роли на сервере.

Для машин без оператора (серверы, киоски) владелец выключает запрос подтверждения на самой машине.

### Как это защищено

- Соединения с сервером идут по TLS; сертификат самоподписанный, клиенты сверяют его отпечаток
  (он входит в код регистрации; консоль запоминает его при первом входе).
- Для каждого сеанса сервер выдаёт одноразовый секрет; экран и ввод дополнительно шифруются им.
- Пароли пользователей и ключи компьютеров хранятся на сервере только в виде хешей.
- Сервер доверенный: тот, кто управляет сервером, может подключаться ко всем компьютерам организации.

## Журнал действий

Журналов два, оба открыты для просмотра и выгружаются в CSV (открывается в Excel).

**Журнал сервера** — вкладка «Журнал» в консоли, доступна всем учётным записям, включая наблюдателей.
В нём: входы и неудачные входы, начало и конец каждого сеанса с режимом и длительностью, отказы в
подключении, принял ли пользователь сеанс или разорвал его, переданные файлы и текст буфера обмена,
изменения пользователей, компьютеров и кода регистрации, а также сами выгрузки журнала.

**Журнал компьютера** — кнопка «Журнал» в главном окне, доступен любому, кто сидит за этим ПК.
В нём то же самое с точки зрения этой машины, включая подключения без сервера (по IP и ID), попытки
с неверным паролем, исходящие подключения и изменения настроек доступа.
Файл: `~/.minideck/journal.jsonl`.

В обоих журналах есть фильтр по периоду и участнику и поиск по тексту.

Что не записывается: содержимое экрана, нажатия клавиш, содержимое файлов и буфера обмена — только
имена файлов, размеры и число символов.

Ограничения: журнал сервера нельзя изменить через программу, но тот, у кого есть доступ к файлам
сервера, может править базу напрямую; журнал компьютера — обычный файл в профиле пользователя.
События «ПК: …» в журнале сервера сообщает сама клиентская программа.

### Хост без окна

```bash
python -m minideck host --password МойПароль --relay relay.example.com
```

В этом режиме подтверждение не запрашивается — доступ только по паролю. Флаг `--view-only` запрещает управление и приём файлов.

## Безопасность

Ключи сеанса выводятся из двух вещей сразу: обмена эфемерными ключами X25519 и пароля (scrypt). Оба значения
подаются в HKDF вместе с полной записью приветствий, поэтому:

- записанный сеанс нечем расшифровать: эфемерные ключи исчезают вместе с ним, поэтому проверять догадки о
  пароле офлайн попросту не на чем — и узнав пароль позже, старую запись уже не открыть;
- неверный пароль по-прежнему выявляется на первом же сообщении;
- остаётся тот, кто **активно** встаёт в середину рукопожатия и говорит с обеими сторонами — именно в такой
  позиции находятся relay и сервер управления. Против этого у каждого компьютера есть постоянный ключ, см. ниже.

**Кто на другом конце.** У каждого компьютера есть постоянный ключ Ed25519 (`~/.minideck/host_key`), которым
хост подписывает запись рукопожатия — первым же сообщением после проверки пароля. Зритель запоминает отпечаток
и при его смене показывает предупреждение с прежним и новым значением; продолжить можно только вручную. Поэтому
тому, кто встал в середину соединения, приходится предъявить ключ, которого зритель раньше не видел.

- свой отпечаток виден в «Настройки → Отпечаток этого компьютера» — его можно назвать по телефону;
- в организации сервер хранит отпечаток каждого компьютера и отдаёт его консоли, поэтому проверка работает уже
  на первом подключении; смена ключа попадает в журнал сервера как «ключ компьютера изменился»;
- «Забыть запомненные ключи» в настройках сбрасывает запомненное — это для законной переустановки на той стороне;
- принятый новый ключ и первое запоминание тоже попадают в местный журнал;
- первое прямое подключение к новому адресу запоминается молча: сравнивать пока не с чем. Если подмену нужно
  исключить с самого начала, сверьте отпечаток по телефону во время первого сеанса.

Остальное:

- Постоянный пароль хранится открытым текстом в `~/.minideck/config.json`.
- Запускайте хост только на своих компьютерах или с согласия их владельца.

Что хост не позволяет сеансу:

- в режиме «только просмотр» — ни ввода, ни файлов, ни записи в буфер обмена этого компьютера;
- неверные пароли считаются по адресу: подбор с одного адреса блокирует только его, остальные
  подключаются как обычно;
- входящий файл ограничен 2 ГБ, весь сеанс — 8 ГБ; отказ попадает в журнал;
- до принятия пароля сообщение больше 64 КБ разрывает соединение;
- одновременно идёт не больше четырёх рукопожатий: обмен ключами стоит памяти, и этот предел не даёт
  потоку подключений её исчерпать.

Эти правила закреплены проверками — `tests/test_security.py`, `tests/test_handshake.py` и
`tests/test_identity.py`; каждый файл запускается как `python tests/test_security.py`, ничего кроме Python и
`cryptography` не нужно.

> **Версии до 0.5.0 не соединяются с 0.5.0 и новее.** Рукопожатие изменилось, и старое не распознаёт новое.
> Обновлять нужно оба компьютера; при попытке соединиться программа прямо скажет, что на другой стороне
> старая версия.

## Частота кадров

Частота выбирается в окне просмотра: **15, 30 (по умолчанию) или 45 к/с**. Это верхняя граница: если
на экране ничего не меняется, кадры не передаются вовсе.

Как снимается экран на Windows:

- **DXGI Desktop Duplication** (основной способ) — около 5 мс на кадр, хватает на 45 к/с;
- **GDI** (запасной) — около 27 мс на кадр, это примерно 22 к/с. Включается сам, если DXGI недоступен:
  экран блокировки, окно UAC, смена разрешения. Каждые 3 секунды программа пробует вернуться на DXGI.
  Принудительно выбрать способ можно переменной `MINIDECK_CAPTURE=dxgi|mss`.

Замеры на одном компьютере (1920×1080, экран постоянно меняется, хост и зритель — разные процессы):

| Цель | Отправлено хостом | Отрисовано зрителем |
|---|---|---|
| 30 к/с | 29–30 | 29,9 |
| 45 к/с | 44,9 | ~40 (когда меняется большая часть экрана) |

По сети частоту ограничивает и канал: при постоянно меняющемся экране это 3–6 Мбит/с, при показе
видео — заметно больше. На медленном канале частота снижается сама, кадры не копятся в очереди;
помогают «Качество: Низкое» и «Размер: 75%/50%».

Пока идёт сеанс, хост не даёт дисплею погаснуть: на погасшем мониторе картинка бы застыла. Если монитор
уже погас, сеанс с правом управления будит его сдвигом мыши на 1 пиксель и обратно; в режиме «только
просмотр» программа ничего не вводит.

## Ограничения

- Транслируется только основной монитор; курсор удалённой машины не рисуется (виден локальный).
- Клавиши передаются как физические (при Windows ↔ Windows): раскладка определяется хостом.
- Ctrl+Alt+Del и окна UAC/экран блокировки недоступны (программа не работает как системная служба).
- Нет звука и передачи файлов с хоста на клиент.
- Проверено на Windows 10; на Linux/macOS код рассчитан работать, но не тестировался.

## Структура

| Файл | Назначение |
|---|---|
| `minideck/proto.py` | рукопожатие, шифрование, формат сообщений |
| `minideck/host.py` | хост: сеансы, приём ввода и файлов, клиент relay |
| `minideck/screen.py` | захват экрана и поиск изменившихся областей |
| `minideck/inputctl.py` | эмуляция мыши и клавиатуры |
| `minideck/viewer.py` | клиент: сетевой сеанс и окно просмотра |
| `minideck/relay.py` | relay-сервер для подключения по ID |
| `minideck/server.py` | сервер управления: учётные записи, роли, компьютеры, журнал |
| `run_server.py`, `Dockerfile`, `deploy/` | запуск сервера: консольный exe, Docker, systemd, автозапуск на Windows |
| `minideck/serverapi.py` | клиент сервера: TLS с проверкой отпечатка, API администратора, агент ПК |
| `minideck/console.py` | консоль администратора |
| `minideck/journal.py`, `journalui.py` | журнал действий и окно просмотра с выгрузкой в CSV |
| `minideck/installer.py`, `setupui.py` | установка, обновление и удаление; мастер установки |
| `minideck/updater.py` | проверка новых версий, загрузка и проверка установщика |
| `minideck/app.py` | главное окно |
| `tests/test_security.py` | проверки границ сеанса: просмотр без записи, лимиты, блокировка по адресу |
| `tests/test_handshake.py` | проверки рукопожатия: общие ключи, свои на каждый сеанс, несовпадение версий |
| `tests/test_identity.py` | проверки ключей компьютеров: запоминание отпечатка, смена ключа, подмена |
